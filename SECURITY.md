# Security model

This agent moves real money on your behalf. Here is what protects you, what
you control, and what to check before running it.

## Built-in rails (enforced in code)

| Rail | What it prevents |
|---|---|
| **Hard consent gate** | The agent refuses ALL setup/trading actions until you personally accept the versioned DISCLAIMER.md (SHA-pinned; re-triggers if the text changes). Scripts and LLMs are instructed never to accept for you, and the one-line installer never touches it. |
| **Dry-run mode** (default ON at setup) | No new orders while you trial the source and policy — actions are logged/notified only. Switching to dry-run later stops new real trades; a position the agent already bought with a real order is still sold for real on its exit signal (it is never left untracked at the broker), and the dashboard says how many such positions are open before you switch. |
| **Pause** (dashboard button / chat `pause`, `resume`) | Stops new entries only. Exit signals, the expiry guard, order reconcile and the broker checks keep running for open positions. Saved in config.json (`"paused": true`), so a restart, crash recovery or update never un-pauses the agent by itself. A start from a damaged memory file is a different, stricter hold — see *State file safety*. So is a move to a server ("Deploy"): while the agent's memory is copied, and from then on, the agent on this computer places no orders at all — exits and the expiry guard included — and `resume` is refused, so the two copies can never both trade. |
| **Daily entry cap** (`max_entries_per_day`, default 5) | A runaway or malicious feed cannot open unlimited positions in a day. Counted from the full trade log — flooding the log with skippable events cannot push today's entries out of view. Mechanical — checked before the LLM policy. Real and dry-run (practice) trades are counted separately: live mode counts only real entries, dry-run only its own practice entries. If the trade log can't be written (full disk, locked file), today's rows are kept in memory, still count toward the cap, and you get an alert. |
| **Open-positions cap** (`max_open_positions`, default 10) | The daily cap resets each day; this one doesn't — total concurrent exposure stays bounded no matter how many days a feed misbehaves. Exits are never blocked. |
| **Event validation** | Ticker/expiry/strike/type are sanity-checked before any instrument lookup; malformed or absurd events are dropped. |
| **Staleness guard** (`max_event_age_s`, default 300) | A machine waking from sleep will not buy into an hours-old entry. Exits are never stale-blocked. An entry whose exit has already arrived (both show up in one poll after a sleep or an outage) is not bought. A `url` feed event with no `occurred_at` counts as old as the time since the agent last read the feed; the last read is remembered across a restart, so a short restart does not lose a new entry. One that was already listed the first time the agent read the feed, or that appeared while the agent was stopped for longer than `max_event_age_s`, is not bought and no alert is sent — there is only a line in the log. The `manual` source is your own commands: each is run once, whenever the agent next reads the file — except an `enter` that the agent first reads together with an `exit` for the same contract: that one is not bought, and you are told. An exit that could not be completed is kept (the newest 50) and retried every loop — also while the agent is paused, because a pause only stops new entries — even after the feed stops listing it. |
| **Auto-pay cap** (`max_autopay_sats`, default 30,000) | The wallet never pays an oversized Lightning invoice, even if a paywall misbehaves. The amount is read from the invoice itself: an invoice with no amount, or one that asks for something other than the price the feed stated, is not paid. |
| **One day-pass a day** (`max_autopay_sats_per_day`, default = one pass) | A paywall that keeps rejecting a valid pass cannot make the agent re-buy: the wallet pays for one day-pass a day, and a pass that is lost or refused is not paid for again — you get an alert instead. Only if you set `max_autopay_sats_per_day` yourself may it buy more, up to that many sats. Each purchase is saved before the wallet pays; if the wallet's answer is lost (a timeout, or the agent crashing or restarting), the agent asks the wallet later and uses that pass rather than buying another. Only the wallet that was asked to pay is believed: if you change wallets while a payment is undecided, the agent does not pay again from the new one (it alerts you instead), and "the wallet has no record of it" only counts as "not paid" once the invoice has expired (about an hour). A payment that failed does not count. If a wallet pays but cannot give the payment receipt (preimage) the pass is made from, the agent stops buying with that wallet and tells you, rather than losing the same sats every day. An invoice the agent refuses, or a payment that fails, is sent to you as an alert — not only printed. |
| **Market days only** | The wallet buys a day-pass only on a market day, from 8:30 AM ET until the close (weekends, market holidays and early closes are respected) — never a pass that would cover no market time. |
| **Contract cap** (`max_contracts_per_trade`, default 100) | Applies to BOTH sizing modes — a typo like `contracts_per_trade: 1000` places at most 100. |
| **Max daily loss** (`max_daily_loss_usd`, opt-in; wizard Safety step or `set max loss 300`) | Once today's **estimated** realized loss reaches the limit, no new entries until tomorrow; exits always run. Estimated from live quotes at entry/exit (falling back to the feed's own paper P&L %) — brokers don't report fill prices to the agent, so slippage isn't counted. Real exits only: a dry-run gain never offsets a real loss (in dry-run the limit is rehearsed on the practice exits). The losing-streak rule is counted the same way. |
| **Exit pairing** | The agent only ever sells positions it opened; dry-run positions can never trigger real orders, and a position bought with a real order is never closed "on paper". |
| **Never sell to open** (every broker, live and practice) | The agent only buys options to open a long position and sells to close contracts the account holds. One check (`brokers/order_guard.py`) runs inside the one function per broker that sends orders and refuses anything else: a sell with any other position effect, a buy that closes, a quantity that isn't a whole number above zero. Right before every sell the agent reads what the broker itself says the account holds of that contract, minus what working sell orders are already selling, and never sells more than that (its own ledger is only an upper bound); holding none, it sends nothing and checks again before any new sell. The broker refuses an opening sell too where it can: Robinhood orders carry `position_effect: "close"`, Alpaca orders carry `position_intent: "sell_to_close"` (and `buy_to_open` on buys). moomoo has no such setting, so while the holdings can't be read a moomoo sell is **held back** (retried every loop; you are told, urgently on the expiry day) — a long option not sold can lose at most what was paid, a short one has no limit. When OpenD answers the holdings read with its query-frequency limit (10 refreshed reads per 30 s per account), the sell waits up to 30 s for the limit to lift and goes out in the same loop. At moomoo the holdings are read through the same connection as the sell, right before it is sent, but nothing at the broker ties the two together: if you sell the same contract in the moomoo app in the fraction of a second between the read and the order, the agent's sell can still open a short. A **short** position found in a contract the agent traded is reported to you at once, new entries are paused (your Pause: only `resume` lifts it), and the agent never trades it — closing it is your call. Signals that could mean a short (an event type other than ENTERED/EXITED, an entry that says sell/write, a negative quantity) are ignored with a logged reason, and a self-edit can't add broker code that sends orders without the check. |
| **One order per signal** (Robinhood, Alpaca) | If the connection fails while an order is being sent (a timeout, a dropped connection, a gateway error), the agent can't know whether the broker took it. It never answers that by sending the order again. It first asks the broker whether the order is there (Alpaca: by the id it sent with the order; Robinhood: in your recent orders) and takes it over if it is. A **buy** it can't find is NOT sent again: the signal is recorded as handled, you get a "check this trade" alert telling you to look in your broker app, and the agent keeps looking for the order (for 10 minutes, or for up to a day while the broker can't be reached). If it turns up, the agent manages the position, logs it as an entry (from then on it counts toward your daily entry cap and the P&L estimate) and tells you; until then it won't buy that contract again. A **sell** is never dropped: on Alpaca the agent waits until Alpaca can say whether the first sell exists (a second plain sell could open a short) and only then sells again; on Robinhood it sells again on the next loop, because its sells can only close contracts you hold. Every order also carries an id made from its signal, so the broker can recognise a repeat of the same order (Alpaca refuses a repeated id). An order the agent's ledger already has is never booked a second time, whatever the broker answers. moomoo orders go through the local OpenD gateway and are not covered by this rail. |
| **Expiry guard** (`expiry_guard_et`, default `"15:45"`; `expiry_alert_et`, default `"15:50"`; either can be `"off"`; chat `expiry guard on\|off\|HH:MM`) | A position the agent opened that is still held on its expiry day is sold from 15:45 ET until the close (marketable limit at bid −5%, retried every ~10 s) instead of risking exercise/assignment if the exit signal was missed. Only the agent's own positions; no sell when the contract has no bid (it expires worthless — you get a notification instead); it keeps running while the agent is paused (but not during the full hold after a damaged memory file — see *State file safety* — or the few seconds of a restart), and in dry-run it still sells positions bought with real orders (dry-run positions stay on paper). Anything still open at 15:50 ET gets one urgent notification and a dashboard banner. At startup and after a sleep, the agent alerts for positions expiring today and, once each, for positions that expired while it was offline. ET times, DST-safe. Past the guard time, no new position is opened in a contract that expires that day. Sell limits under $0.10 go out at the bid itself, and every limit is on a tick all option classes accept ($0.05, or $0.10 from $3). On 1:00 PM early-close days both times move 3 hours earlier (12:45/12:50, never before 09:30): the agent applies the NYSE rules (the day after Thanksgiving; Dec 24 and Jul 3 when Monday–Thursday) — add others with `early_close_days` (list of `YYYY-MM-DD`). It skips NYSE full holidays (options don't expire on them). |
| **Exit remainders and ledger check** | An exit that leaves contracts held (partial fill; order dead or cancelled with quantity left) is re-sold by the agent every loop during market hours (09:30 to the close; resumes at the next open): marketable limit, sell-to-close, capped at the ledger remainder AND at what the account holds (an unreadable account — or a broken broker connection — waits; only Robinhood's close-only exits sell the ledger remainder after 10 min of unreadable holdings, at most 3 times, then alert; with `position_sync: false` there is no re-sell, only an alert). When the account holds fewer than the ledger remainder, only what the agent's own filled orders account for is sold (order history: its buys minus every sale since). No sell into a zero bid. Trading days only: NYSE full holidays are skipped (built-in calendar; add closures with `market_holidays`, list of `YYYY-MM-DD`); one holdings read a minute during the 9:28–9:40 ET open rush. Agent-only event fields (`max_qty`, `exit_limit`, `exit_cause`…) are stripped from feed events. One notification when found, when cleared, and if still open at 15:50 ET. A contract the agent bought that the account holds more of than the ledger lists is re-added only up to what the agent's own filled orders account for (its buys minus every sale since), proven from the broker's order history by the agent's own order ids; never the owner's positions; without order history, an alert only. moomoo exits are now checked for fills (a sell still working after ~15 s is cancelled and settled with what filled). |
| **LLM policy brain — veto-only** | The LLM can only BLOCK entries against YOUR written policy; it can never initiate, enlarge, or redirect a trade. On any LLM error the default is skip (fail-safe). Events fed to it are treated as untrusted data — embedded "ignore the policy" text is grounds for a veto, and the worst-case injection outcome equals not having a policy at all. |
| **File permissions** | `~/.agentic-trader/` is `0700`; config (wallet admin key, API keys), `state.json` and its backup `state.json.bak` (day-pass token), the dashboard token and broker tokens are `0600`. On Windows the folder's inherited ACL is replaced with one granting only your user (via `icacls`). |
| **State file safety** | `state.json` is the agent's memory: open positions, signals already handled, the paid day pass. Every save is written to disk before it replaces the old file (on macOS including the drive's own cache), and a second copy (`state.json.bak`) is written right after it. If the system reports it could not write a save (failing disk, full disk), the old file and its backup are left as they were. If the backup can't be updated you get an alert and a dashboard notice. If the file is damaged at startup, the agent loads the backup and tells you; it cannot compare the two, so it asks you to check your positions against your broker account. If the backup was written before the damaged file (even slightly), or there is none, it keeps the damaged file under a new name (`state.json.damaged-…`), alerts you and starts **on hold**: the dashboard shows it as paused, but it is stricter than the Pause button — no orders at all (no entries, no exits, no expiry-guard or re-sell orders; the alerts still go out) and no feed payments — until you press Resume (or type `resume`). If the file is there but can't be opened (another program is using it, it belongs to another user), the agent changes nothing, does **not** start, alerts you once a day and tries again at every start. It never silently starts from an empty memory. |
| **Web UI localhost-only + login** | The combined setup wizard + dashboard (127.0.0.1:8721) binds localhost exclusively — nothing is exposed to the network; remote access requires an SSH tunnel. Every page and API call also requires a per-install secret (`~/.agentic-trader/ui_token`), handed to your browser once via the login link the agent prints/opens (`python agent.py link` prints it again) and kept in an HttpOnly cookie — other OS users and web pages can't drive it. (A program running as *your* user can read the token file, as it can any of your files.) The dashboard chat is a fixed command allowlist plus answer-only LLM Q&A; it cannot place trades. |
| **Verified-source updates** | The Update button only pulls from github.com/traderhc123/agentic-trader (forks: set `AGENTIC_TRADER_UPDATE_REMOTE`), shows the incoming commit list first, and installs exactly the commit you reviewed — if anything new lands in between, nothing is installed. Fast-forward only, so local edits are never overwritten. |
| **Self-edit — human merge gate** | Off by default (`self-edit on` to enable). The agent's LLM can WRITE changes to its own code, but nothing applies until the owner reviews the unified diff in the dashboard and clicks Apply; applies are backed up, compile-checked, and auto-rolled-back on failure; and a **FOUNDATION layer is immutable to the agent**: agent.py (consent gate + safety pipeline), self_edit.py (the governor itself), llm_policy.py, llm_client.py, lightning_wallet.py, webui.py, platform_compat.py, keep_running.py (the one-copy lock), broker_events.py (dropped-trade reporting), rules.py (the owner's built-in entry rules), dry_run_preview.py (what the dry-run preview says your rules would do), view_model.py (what the dashboard says the agent is doing and will do), transfer.py (the passphrase-locked move file), requirements.txt, DISCLAIMER.md, SECURITY.md, install.sh, install.ps1, LICENSE, and every **existing** module in `brokers/` and `sources/` (the order and signal paths) can never be self-rewritten — the agent may only ADD new adapters there (registry edits are flagged in the review) — — enforced at both propose and apply time, case-insensitively and against Windows name aliasing (`Agent.py`, `agent.py.`, `agent.py:stream`). A prompt-injected proposal can only sit unapplied in a diff view, and can never target the foundation at all. |
| **HTTPS enforcement** | Custom feed URLs and wallet URLs must be HTTPS (or localhost) — signals and spend keys never travel cleartext. |

## What YOU control (read before going live)

- **Robinhood blast radius**: the agent can only trade the dedicated Agentic
  account. Fund it with exactly what you're willing to lose; your main
  account is untouchable by design (Robinhood enforces `agentic_allowed`).
- **Wallet blast radius**: the agent's auto-created wallet lives on a hosted
  LNbits instance (custodial — the operator of that instance technically holds
  the sats; default demo.lnbits.com, override with AGENTIC_TRADER_LNBITS or
  bring your own). ⚠️ demo.lnbits.com is a **public test server** — it can be
  reset or go offline and its balance lost; the wizard, setup and `doctor`
  warn whenever you're on it. On a demo instance keep only a few days of
  passes; on your own/paid instance, ~a month of feed fees, nothing more.
- **API keys**: the AI key (policy brain / Q&A — any provider) should be a
  dedicated key with a spend limit set in that provider's console. Keys are
  only ever sent over HTTPS, or to a model on this computer (localhost).
- **Model choice**: the policy brain is veto-only, and any error, refusal or
  reply that isn't a clear JSON yes/no skips the trade. A weaker model can
  still misread your policy or be swayed by text inside an event — the worst
  case is the same as having no policy at all. Prefer a capable model.
- **Machine hygiene**: anyone with access to `~/.agentic-trader/` has your
  wallet key and broker session. Run on a machine you control; full-disk
  encryption recommended; don't run on shared hosts.
- **Watch it**: configure notifications (Discord/ntfy/Telegram). Autonomous
  and silent is the failure mode — every action, veto, and error notifies.

## Threat model notes

- **Malicious/compromised signal source**: bounded by validation + staleness
  + the daily cap + your policy + 1-contract-scale sizing. A bad source can
  at worst open `max_entries_per_day` positions of your configured size per
  day until you stop it — set the cap accordingly.
- **Prompt injection via feed content**: the policy brain's system prompt
  pins it to veto-only judgment of your policy; injected instructions in
  event fields cannot make it exceed that authority (approving is the
  ceiling, and that equals mechanical mode).
- **This template is code you should read.** ~900 lines total, dependency
  surface is `requests` + the official `anthropic` SDK. Pin or vendor if
  you fork.
